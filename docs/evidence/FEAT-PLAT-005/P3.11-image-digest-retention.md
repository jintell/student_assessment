# P3.11 Previous Image Digest Retention

The registry policy in `config/image-retention-policy.yml` retains at least the
current and previous releases and protects every digest referenced by a release
manifest. Referenced digests are immutable and are excluded from ordinary
untagged-image cleanup.

The release manifest stores N-1 as `previousImageDigest`; a tag or source commit
is not a substitute. `ci/verify-previous-image` resolves the exact
`ghcr.io/meldtech/cbt-platform@sha256:...` subject before stage 12 proceeds. A
missing manifest, malformed digest, unavailable registry client, authorization
failure, or missing registry object is a blocking failure with no skip path.

Registry administrators must run a reference audit against retained release
manifests before deleting any digest older than 90 days. The later compatibility
runner consumes only the digest that this preflight verified.
