# P9.8 Migration Observability Conformance

Verdict: **CONFORMING CONTRIBUTION - ALERT REGISTRATION OPEN**

## Per-release recording

| Signal | Producer | Release correlation | Retained evidence |
|---|---|---|---|
| `migration_duration_seconds` | Migration-only Job around each attempted module | OTLP resource `service.version`, environment resource, classification tag, and immutable Job/manifest evidence | Job execution record and release manifest |
| `migration_lock_held_seconds` | Stage-12 `LockMeasurementHarness` adapter | Manifest release/classification and checksums in the matching report | `migration-lock-duration-report.json` and Markdown summary |
| `migration_outcome_total` | Migration Job and stage-12 verifier | OTLP resource plus classification/outcome tags; stage 12 records success, static refusal, and lock-threshold failure | Job status, stage-12 report, and manifest |
| `migration_forbidden_operation_total` | Stage-12 analyser refusal path | Manifest classification and bounded rejection-code tag | Blocking stage-12 result |
| `deploy_freeze_refusal_total` | Deploy-freeze precondition | Deployment evidence carries release/attempt; metric carries bounded reason only | Freeze decision and emergency-override audit event |

The Kubernetes Job sets `OTEL_SERVICE_NAME=cbt-platform-migration` and resource
attributes for the release identifier and target environment. Release IDs are
resource metadata, not metric labels, which preserves bounded series
cardinality while keeping each Job run attributable to its immutable manifest.

## Threshold breach behavior

A stage-12 threshold breach produces all three of these signals:

1. a non-zero blocking gate result;
2. a retained report naming the relation, lock mode, measured hold, threshold,
   dataset provenance, and migration checksum; and
3. `migration_lock_held_seconds` plus
   `migration_outcome_total{outcome="LOCK_THRESHOLD_FAILED"}`.

The breach is therefore alertable and is not merely a log line. The proposed P2
lock alert, P1 production failure alert, dashboard panels, routing, and exercise
criteria are recorded in `docs/defects/TASK-PLAT5-OBS-001.md`.

## Ownership and residual gap

`FEAT-PLAT-005` owns instrumentation, bounded labels, retained evidence, and the
alert proposal. `FEAT-OBS-001` owns platform registration of the metric
contract; `FEAT-OPS-004` owns alert rules, routing, dashboard presentation, and
exercise evidence.

Until `TASK-PLAT5-OBS-001` closes, the feature has supplied alertable telemetry
but cannot claim that the production alert is registered or exercised. That
external ownership gap does not permit downgrading stage 12, increasing lock
thresholds, or treating logs as the alert substitute.
