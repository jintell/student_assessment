# P5.1 Outbox Operator Interface Handover

Status: **PUBLISHED TO `FEAT-OPS-002` AND `FEAT-GRD-005` OWNERS**

`FEAT-PLAT-004` has no frontend and owns no operator HTTP route. It provides
the backend data and command boundary used by the operator features; those
features own authorization, presentation, routing, pagination, and their
external API contracts.

| Consumer | Visibility owned by consumer | Interface supplied by `FEAT-PLAT-004` | Consumer obligation |
|---|---|---|---|
| `FEAT-OPS-002` | Platform-wide outbox backlog, oldest pending age, `FAILED` rows, and `integration.dlq` inspection | Fixed-state backlog and oldest-age metrics, relay persistence queries, and `outbox::api`'s `OutboxRedriveCommand` with typed failed-row and dead-letter requests | Expose the authorized operator workflow; redact payloads by default; require actor, reason, and idempotent request identity; show the audited outcome |
| `FEAT-GRD-005` | Grading recovery view for grading-owned failed propagation | The same generic failure metadata and redrive command, filtered by the grading event ownership boundary | Keep grading-specific diagnosis and recovery in the grading operator surface; do not add a second relay, DLQ consumer, or redrive implementation |

The query boundary returns operational metadata only: event identity and type,
aggregate reference, state, attempt count, classified failure reason,
correlation identifier, and timestamps. Backlog metrics use the closed
`PENDING`, `CLAIMED`, `PUBLISHED`, and `FAILED` state labels and never use
`tenant_id` as a metric label. Payload access, where an incident workflow
truly requires it, remains separately authorized and is not part of a list
query.

The command boundary is
`org.meldtech.platform.outbox.api.OutboxRedriveCommand`. It supports a
`FAILED` row and a recognized dead-letter reason, preserves the original event
identity, records actor and reason through the audit port, and checks the
consumer guard before a dead-letter effect can be repeated. It deliberately
has no controller, router, or web annotation.

No HTTP route, request or response DTO, OpenAPI operation, or frontend asset is
introduced by `FEAT-PLAT-004`. Consequently the HTTP/OpenAPI breaking-change
diff has no feature-owned surface to assess. Event-schema compatibility remains
a separate blocking Stage 9 concern and is not an operator API.
