## What the drill proves

Production migrations create a new database. Synthetic registered v1 events are
committed through `app_delivery` tenant scope. The production sampler/runtime
uses the secured worker pool and real persisted rows. Prometheus scrapes the
authenticated management endpoint, evaluates the existing rule, and sends
alerts to Alertmanager, which delivers firing/resolved envelopes to the local
receiver. Grafana loads the committed dashboard and its provisioned datasource
returns the measured backlog/age/freshness values. Evidence uses dashboard query
results, not an unexecuted screenshot claim.

The local-only relay hold control allows PENDING rows to accumulate while
collection continues. Resuming it uses production claim, confirmed RabbitMQ
publication and publication-store adapters. No event state is edited to clear
an alert. Published and broker-queue counts must equal 5,002 committed events
after both scenarios. This fixture assembly does not close P8.5 production
assembly or rerun the consumer/business-effect acceptance assertions.

Local settings: collection/scrape/evaluation 5 seconds, expiry 15 seconds, query
timeout 2 seconds, notification group wait 1 second/group interval 5 seconds,
repeat 1 minute, `send_resolved: true`. Depth >5000 OR age >300 seconds, p2, no
`for` duration remain unchanged. These settings are local test inputs, not owner
approval of production timing or performance budgets. The rendered rule changes
only the runbook annotation to a working local runbook endpoint.
