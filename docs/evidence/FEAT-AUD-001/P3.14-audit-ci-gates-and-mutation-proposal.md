# P3.14 Audit CI Gates and Mutation Proposal

## Gate Configuration

`config/audit/ci-gates.yaml` is the feature-owned gate map.

| Stage | Gate | Configuration |
|---|---|---|
| 8 | Daily open-chain verification | `ciStage8` depends on `auditDailyChainVerificationTest`, a tagged PostgreSQL Testcontainers walk that checks every fixture shard from deterministic seed through event link to committed head. |
| 10 | Audit-payload secret scan | `ciStage10` depends on `auditPayloadSecretScan`. Integration tests must produce JSON captures; missing or empty capture directories fail closed. The scanner uses the kernel `SecretFieldPattern`, permits the required `policy_key`, and has a planted nested-PIN self-test. |
| 6 | `audit.domain` mutation testing | `config/audit/stage-6-pitest-proposal.yaml` defines the proposed PIT scope, subjects, and 90% thresholds. It remains `PROPOSED` because neither `audit.domain` nor a repository Stage 6 exists in this phase. |

Both active gates are blocking Gradle dependencies of their named CI stages.
The Stage 10 capture contains synthetic values only and never reports a
detected secret value in its diagnostic.

## TASK-AUD1-OBS-001 Proposal

Add the pure `org.meldtech.platform.audit.domain` package to a blocking PIT
mutation stage when Phase 4 supplies the package. The proposal applies a 90%
mutation threshold without class exclusions to canonical JSON, record hashes,
shard assignment, epoch identity, epoch-root derivation, and root-chain input
derivation.

This follows the reasoning already used by plan section 19.3 for scoring and
state machines: example-based tests can all pass while a plausible algorithm
is wrong. Chain algebra has the same risk, with a sharper failure mode. A
symmetric defect copied into both the hash producer and verifier can produce
internally consistent examples while proving the wrong history. Examples
include reversing concatenation order, using a signed remainder, dropping a
domain separator, sorting shards lexically, accepting a missing empty-shard
sentinel, or binding the next root to the wrong sequence. Golden vectors catch
known byte drift, but mutation testing demonstrates that the surrounding
properties and negative tests distinguish these plausible wrong algorithms.

### Activation Decision

Platform CI owns creation and placement of the missing Stage 6 job. Audit owns
the target package, tests, thresholds, and surviving-mutant remediation.
Activation requires the prerequisites in the proposal configuration and an
approved resource budget. Once activated, a surviving mutation or a threshold
below 90% blocks the pipeline; lowering the threshold or excluding a chain
subject requires an architecture decision.
