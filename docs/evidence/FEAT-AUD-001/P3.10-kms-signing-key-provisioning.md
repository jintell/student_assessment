# P3.10 Audit Signing Key Provisioning Record

Date: 2026-10-07
Feature: `FEAT-AUD-001`
Status: provider-neutral provisioning contract complete

The deployment contract provisions one non-exportable asymmetric KMS key per
environment. The dedicated `cbt-audit-sealer` workload identity alone may
sign. The verifier may obtain public-key metadata, while API, ordinary worker,
PIN distribution, migration, and retention identities are explicitly denied.
The security administrator can rotate and administer the key but cannot sign.

Provisioning artifacts:

- `deploy/kms/audit-signing-key-policy.json.template`
- `deploy/kubernetes/audit-sealer-service-account.yaml.template`
- `deploy/kubernetes/audit-sealer-deployment.yaml.template`
- `config/security/secret-inventory.yaml`

Environment deployment must substitute the provider key reference and
workload identities through the release secret/configuration system. The
private key, credentials, provider policy output, and raw signing failures are
never stored in this repository, an image, a ConfigMap, a log, or an audit
payload. Deployment readiness verifies the key is enabled, asymmetric,
environment-owned, non-exportable, and grants `Sign` only to the sealer.

Rotation is annual and immediate on suspected disclosure or signer
offboarding. Old public-key versions remain available for at least the longest
five-year evidence lifetime. Rotation changes the recorded key version and
never re-signs an existing checkpoint or seal.
