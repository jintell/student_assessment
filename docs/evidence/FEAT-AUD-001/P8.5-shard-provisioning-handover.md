## Parameter and ordering

- Approved provisioning default: `N = 64`, initial policy version 1. The
  `AuditShardPolicy` value type accepts 1–1024, but that validation range is not
  approval to change the deployment default.
- Provision before enabling any tenant writes. Persist the tenant policy and
  create the required initial heads through the approved provisioning identity;
  request-time append only locks/advances existing heads and must not silently
  create missing topology.
- Epoch identity is `(retention_class, UTC calendar month YYYY-MM)`. `N` is
  immutable inside an epoch; `shard_id` is a column, not a partition key.
- A change requires closed current epochs, an unopened future epoch, an
  approved new version and `audit.AUDIT_SHARD_POLICY_CHANGED.v1` evidence.
  The event records previous/new count, effective period and policy version.
  Provision topology and append the change evidence atomically through the
  reviewed tenant transaction; a failed append must roll back the change.

## Implemented seam and consumer work

`TenantAuditShardProvisioning.provisionDefault(tenantId, firstEpoch, recordedAt)`
and `changeAtEpochBoundary(tenantId, newShardCount, effectivePeriod,
policyVersion, actor, recordedAt)` are the current application-layer seam.
`DefaultTenantAuditShardProvisioning` delegates storage and the unopened-epoch
check to `AuditShardPolicyRepository`; it emits policy-change evidence through
the kernel emitter. The three existing provisioning tests pass for default
64, future unopened-epoch change with emission, and in-place-change refusal.
