## Consumer contract

The [P2.17 design](phase-2-architecture-design.md#p217-tenant-scoped-compliance-query-slice)
defines a workforce-only, tenant-scoped `AUDIT_COMPLIANCE_READ` capability
decision from the authoritative platform view. Tenant identity comes from
`ActorContext`, never a query parameter. Query and read-audit emission share
the approved secured caller transaction. A page is returned only after append
succeeds, with `Cache-Control: no-store` and no payload, secret or signature
material in its DTOs.

Three filter modes are defined: tenant timeline, paired entity type/id, or
event type. Inclusive `occurredFrom` and exclusive `occurredTo` bound the
query; entity and event-type modes cannot be combined. Keyset pagination uses
an authenticated, tenant/filter-bound cursor, default page size 100 and maximum
500. `items`, `nextCursor` and `hasMore` are required; `nextCursor` is empty
exactly when `hasMore` is false. Cursor format is opaque to clients.

event JSON Schemas under `contracts/events`, their consumer compatibility and
payload policy. It neither reads this OpenAPI document nor runs an HTTP

boundary, rather than presenting this component as an unauthenticated endpoint.
