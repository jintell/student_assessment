[P0.8 contract](../../../ci/dor/FEAT-AUD-001/P0.8-audit-contract-dor.json),

## Consumer interface

`AuditEmitter.emit(AuditEvent event, ActorContext actor, Instant occurredAt)`
returns Reactive Streams `Publisher<Void>`. A feature imports the kernel port,
`AuditEvent`, `EntityRef`, `RetentionClass` and the closed `CanonicalValue`
payload types; it must not import audit domain, application or infrastructure
implementation packages. Required values are explicit and non-null; retention
candidates are a non-empty immutable set. The controlled clock supplies the
occurrence instant. The authenticated/job actor supplies stable identity,
tenant and correlation context; clients must not select attribution.

Compose the publisher into the caller's secured reactive transaction after
business SQL. It locks the provisioned predecessor head, then inserts the event
and conditionally advances the head with one CTE on that same connection.
Completion means append statements completed, not that the caller committed.
Append failure must fail the whole transaction; business rollback must also
discard the audit record. No separate connection, REQUIRES_NEW, independent
subscription, async fallback or swallowed error is permitted. A privileged
read returns no page before its own audit append succeeds.

The current emitter requires a tenant actor and rejects tenantless platform
actors. Platform-global audit emission is not implemented; a placeholder
tenant must never be used to work around that boundary. Retention/shard
providers, head provisioning and the caller transaction must exist before use.
The no-secret field policy applies in every environment.

## Catalogue convention

An event identifier is `<bounded-context>.<EVENT_CODE>.v<major>`:

- Bounded context: `[a-z][a-z0-9]*`, the owning module.
- Event code: `[A-Z][A-Z0-9]*(?:_[A-Z0-9]+)*`; exactly the same token as the
  FEAT-OBS-001 `eventCode`, without aliases or case conversion.
- Major: positive integer; breaking meaning/payload changes require a new
  major. An issued identifier cannot be renamed, reused or repurposed.

Before emission, the owning feature supplies a reviewed catalogue declaration
with `event_type`, `owner`, `purpose`, `retention_class` (or selection rule),
`payload_schema_version` and `eventCode`. P2.3 additionally requires entity
reference type, tenant-scope policy and privileged-read classification. Include
payload/classification tests and success/rollback coverage in that feature.
Audit records, outbox events, operational logs and business metrics are separate
contracts; one does not replace another.

The signed convention is normative now. The generated catalogue and runtime
registration enforcement described in the
[P2.3 design](phase-2-architecture-design.md#p23-audit-event-catalogue-convention)
are not established by the current `AuditEvent` constructor: it validates the
name shape, required values and candidates, not catalogue membership. The
catalogue publication/generation work remains in P10.1; no future task is marked
complete by this interface record.

## Compatibility and verification

Changes to the approved convention require the Architecture Owner approval
and FEAT-TENANT-001 acknowledgement prescribed by P0.8. Do not alter historical
event semantics or hashes. Consumers must retain older event versions while
their evidence is retained. The existing `R2dbcAuditEmitterTest` exercises
explicit attribution, failure propagation, tenantless rejection and secret
payload rejection; blocking conformance enforces the module/kernel and
transaction boundaries. P7.5/P7.7 retain the real PostgreSQL atomicity evidence.
