# P8.6 integrity metrics — FEAT-OBS-001

Repository registration request published 2026-10-17. Audit owns measured
facts and instrumentation; FEAT-OBS-001 owns naming, bounded dimensions,
registry budgets and export conventions. This is a handover, not live metric
registration. The current `config/observability/metric-cardinality.json` has no
audit entries. P9.1–P9.3 implement and verify those registrations later.

| Required name (architecture §16.2) | Meaning / measurement requirement |
| --- | --- |
| audit_chain_verification_result | Scheduled verification outcome, with failed/missing/stale runs distinguishable from a current success |
| audit_emit_failure_total | Each failed emission that propagates to and fails the business transaction |
| audit_chain_head_lock_wait_seconds | Measured predecessor-lock wait; histogram supporting p95/p99, not total SQL/request duration |
| audit_chain_shard_skew | Maximum/median records per shard over a defined observation window, with explicit empty/zero-median semantics |
| audit_checkpoint_overdue_count | Open tails overdue under the checkpoint policy |
| audit_epoch_seal_total | Seal outcomes using a closed result vocabulary |
| audit_epoch_disposition_total | Outcomes DISPOSED, HOLD_SUSPENDED, VERIFY_FAILED |
| audit_epoch_seal_cas_retry_total | Each lost root CAS that causes recomputation; retry exhaustion remains observable |
| audit_root_chain_fork_detected_total | Any fork detection; verified healthy baseline is zero, absent instrumentation is not zero |
| audit_root_chain_seq | Current root sequence, with explicit tenant-context drilldown and no misleading sum across tenants |

Follow [the metric catalogue](../../metric-catalogue.md): lowercase snake case,
counters ending `_total`, seconds as the duration base unit, closed label values
and explicit `maxSeries` budgets. Account for common `runtime_role` and every
histogram bucket/outcome combination. Never label series with tenant IDs,
correlation IDs, raw entities, SQL, exceptions, credentials or per-shard IDs.

TASK-AUD1-OBS-001 remains open: the architecture requires per-tenant/per-shard
diagnostics while the registry forbids their unbounded series. Register bounded
aggregate measurements with filtered exemplars/protected drilldown, and retain
tenant-specific starvation detection outside unbounded metric labels. A global
average that hides a hot tenant does not meet the alert requirement. Agree the
root-sequence representation, skew zero semantics, windows, histogram buckets
and series budgets in P9.1/P9.2; none is silently fixed by this handover.

Existing seams include `AuditSealTelemetry.compareAndSwapRetry`,
`AuditSealAlertSink` and `AuditEvidencePreservation.recordHighSeverityMetric`.
They are not proof of a deployed Micrometer adapter: a no-op seal telemetry
implementation exists and must not become a production readiness signal.

Consumer closure requires registered meters, exact cardinality budgets,
`metricCardinalityGate`/`telemetrySchemaGate` success, real increment/freshness
evidence and failure-path tests. A6 additionally needs measured answer p95,
audit share of transaction time, lock wait/skew and root density under its
actual workload; metric naming alone does not complete the missing P7.24 harness.
