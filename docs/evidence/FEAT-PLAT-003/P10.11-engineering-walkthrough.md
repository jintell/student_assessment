## Walkthrough Performed

### 1. Required-parameter rule

Reviewed `docs/kernel-usage.md` and the actor/tenant conformance rules.

- Every write path receives an `ActorContext`; tenant-scoped work also receives
  the definitive `TenantId` explicitly.
- Typed identifiers are not interchangeable, and system work uses the closed
  `SystemActor` enumeration.
- No no-argument overload may invent actor, tenant, correlation, or time
  context. HTTP and message adapters resolve context once and pass values
  inward; domain code does not read Reactor context, MDC, headers, or
  thread-local state.

Decision: a write API that cannot show its attribution and tenant scope at the
call site is not an acceptable kernel consumer.

### 2. Allowlist mapper

Reviewed `docs/error-catalogue.md` and `docs/error-authoring.md`.

- `src/main/resources/error-catalogue.yaml` is the single declarative source
  for runtime definitions, OpenAPI schemas, examples, and client documentation.
- `ProblemDetailMapper` is the only construction site. Catalogue text, never an
  exception message, supplies public `detail`.
- Unknown exceptions and mapper failures produce the fixed
  `CBT-PLAT-INTERNAL` response with a correlation identifier.
- CI rejects undeclared codes, fields, extensions, construction sites, direct
  problem writers, and leaked stack, SQL, provider, or secret content.

Decision: a new public error begins with a complete catalogue entry and passes
the blocking allowlist suite; local response-body construction is prohibited.

### 3. Clock and decimal prohibitions

Reviewed `docs/kernel-usage.md` and `docs/decimal-arithmetic.md`.

- Application code injects the kernel `Clock`; `SystemClock` is the only
  production adapter allowed to read ambient current time.
- Scoring uses `BigDecimal` with `MathContext.DECIMAL128`, `NUMERIC(12,4)` raw
  scores, and `NUMERIC(9,6)` full-precision percentages.
- `Decimal.roundHalfUpToWholeNumber` is the sole whole-number rounding helper.
  Binary `double`, `float`, `Double`, and `Float` are prohibited in scoring.

Decision: ambient time and binary floating point are build-failing defects,
not review-time preferences.

### 4. Idempotency decision rule

Reviewed `docs/idempotency.md` and the executable route rule.

- A durable-record operation uses a named PostgreSQL unique constraint,
  deduplication row, or durable state guard. It may not rely on Redis.
- `REDIS_HEADER` is permitted only for a `POST` transition that creates no
  durable domain record.
- `RESERVED` alone permits execution; `REPLAY` returns the stored response;
  `UNAVAILABLE` refuses the transition without a side effect.
- Candidate-path correctness does not depend on Redis availability.

Decision: route authors declare the mechanism and concrete database protection
in `@IdempotencyPolicy`; CI rejects a declaration that weakens durable safety.
