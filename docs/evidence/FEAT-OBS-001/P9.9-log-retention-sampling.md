# FEAT-OBS-001 Log Retention and Sampling Record

Verdict: **CONFIGURED AND DISTINCT FROM AUDIT**

The canonical log-sink input is
`config/observability/log-sink-policy.json`. It names the signed collector
contract's `cbt-platform-logs` logical store and fixes operational-log
retention at `P30D`.

The baseline sampling policy is explicit: retain 100% of events that pass the
application's typed schema and fail-closed redaction boundary. There are no
content-based sink rules in version 1. A future sampling reduction is a
reviewed operational-contract change and must preserve every request/error
diagnosability obligation, security signal, and published dashboard/alert
input. The application can still lose telemetry through its bounded
best-effort queue; those drops are measured and never retried through an
unbounded request-path mechanism.

| Concern | Operational logs | Audit evidence |
|---|---|---|
| Store | `cbt-platform-logs`, reached through OTLP and owned by Platform Ops | PostgreSQL `audit` schema/store, owned by `FEAT-AUD-001` |
| Retention | Fixed `P30D` | Category-aware 12-month, 2-year, and 5-year/result-lifetime classes with longest-wins and legal-hold rules |
| Sampling/drop | Explicit retain ratio `1.0` at the sink; bounded application drops are allowed and counted | Sampling and dropping prohibited; required audit failure rolls back the protected transaction |
| Access | Operations/support least privilege under the observability service boundary | Separately authorized tenant-scoped compliance/audit access; privileged reads are audited |
| Purpose | Diagnosis, performance, and incident triage | Durable evidence of state changes and privileged reads |

The two paths may share an opaque correlation identifier and stable event
code for navigation, but neither delegates to the other. The conformance test
`ObservabilityAuditSeparationTests` enforces package/dependency separation,
and the Phase 6 review confirms the observability adapter cannot write the
audit API or store.

The current repository contains only the `AuditEmitter` API, not the full
`FEAT-AUD-001` store adapter. This record therefore confirms the distinct
retention/sampling contracts without claiming that the future audit feature
is implemented.
