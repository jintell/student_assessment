## Walkthrough Performed

### 1. Port, not vendor

Reviewed `docs/observability-architecture.md` and
`docs/instrumentation-authoring.md`.

- Domain and slice code express telemetry through the framework-free
  `BusinessEventRecorder` and `RequestTelemetry` kernel ports.
- Micrometer, OpenTelemetry, registries, exporters, encoders, and
  `platform.infra.observability` implementations do not belong in `domain` or
  `slice` packages.
- A business event is recorded by the owning application path after commit.
  An HTTP filter can observe a request but cannot know whether a domain
  transition committed, replayed, retried, or did not occur.
- `TelemetryBoundaryConformanceTests` blocks direct vendor dependencies and
  unauthorized business-event adapters in CI stage 4.

Decision: feature code selects semantic facts through kernel ports;
infrastructure alone translates them into vendor telemetry.

### 2. Structured-log schema

Reviewed `docs/logging-contract.md`.

- Non-local output is one JSON object per stdout line.
- Every event carries timestamp, level, logger, message, correlation and trace
  identity, runtime role, module, and slice.
- Actor/tenant, business event, error, duration, and query-count fields are
  emitted only under their documented conditions. Actor fields and request
  measurement fields are inseparable pairs.
- `correlationId` is an opaque join key across responses, problem details,
  logs, spans, exemplars, and asynchronous carriers; it contains no business
  or personal meaning.

Decision: field additions require contract, privacy, security, and conformance
updates; renaming or removing a published field is a breaking change.

### 3. Redaction allowlist

Reviewed `docs/telemetry-hygiene.md` and the shared-kernel
`SecretFieldPattern`.

- `pin`, `otp`, `token`, `secret`, `password`, `key`, and `authorization` are
  prohibited whole segments across telemetry surfaces.
- `policy_key` is the sole exact permitted `key` leaf. It does not permit
  `apiKey`, `encryption_key`, or arbitrary `*_key` additions.
- Secret-named fields are omitted; `[REDACTED]` is defense in depth, not
  permission to publish a prohibited field name.
- Email, personal names, answer content, bodies, SQL parameters, provider
  payloads, and raw exceptions are excluded. The blocking stage 10 scanner
  rejects prohibited field paths and adversarial secret values without
  echoing them.

Decision: any allowlist addition is made once in the kernel after Security
review; no feature-local redaction exception is acceptable.

### 4. Business-event enumeration

Reviewed `docs/metric-catalogue.md` and the executable completeness gate.

The closed MVP set is:

| Event code | Metric |
|---|---|
| `EXAM_STARTED` | `exam_started_total` |
| `EXAM_FINISHED` | `exam_finished_total` |
| `PIN_VALIDATION` | `pin_validation_total{outcome}` |
| `RESULT_PUBLISHED` | `result_published_total` |
| `CORRECTION_APPLIED` | `correction_applied_total` |
| `PROVISIONAL_FEEDBACK_RELEASED` | `provisional_feedback_released_total` |

Sync and payment outcomes are explicitly Post-MVP and declared absent. A
feature records the selected event after commit through
`BusinessEventRecorder`; direct metric registration or filter inference is
prohibited.

Decision: changing the enum, registrations, or metric catalogue requires all
three to remain complete and aligned; a naming convention alone is not proof.

### 5. Per-route query budget

Reviewed `docs/query-budget.md` and
`config/observability/query-budgets.json`.

| Route class | Approved budget |
|---|---:|
| Timer/state refresh | 1 |
| Question navigation | 1-2, exact value registered per route |
| Answer save | 6 |
| Authorized workforce | 2 fixed + owning slice budget |
| Exam entry | Approximately 10 for planning; exact value registered per route |

`dbQueryCount` increments for every executed R2DBC statement in the
request-local Reactor context, including failed or cancelled executions, and
is independent of trace sampling. The current Phase 0 reference route has
fixed overhead 2, slice budget 1, and maximum 3.

Decision: an over-budget route is a design regression. Remove redundant work
or obtain architecture and performance approval for a justified exact change;
never silently raise, omit, average, or sampling-gate the budget.
