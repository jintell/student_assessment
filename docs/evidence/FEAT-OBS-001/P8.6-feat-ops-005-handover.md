## Per-Request Count

`dbQueryCount` is a non-negative count attached to every request-completion
log event. `TracingConnectionFactory` increments a Reactor-context-scoped
counter for each executed statement, independent of trace sampling. It emits
the final count on success, error, timeout, and cancellation, so a sampled-out
trace cannot hide a query-budget regression.

The count is request-local and carries no SQL, parameter, connection, actor,
tenant, or correlation value. `FEAT-OPS-005` should aggregate it by the closed
route/slice metadata already present in the operational event and retain the
individual correlation join only in protected logs.

## Query-Duration Metric

`db_query_duration{slice,operation}` is the registered timer. `slice` comes
from the reviewed slice catalogue and `operation` from the closed
`RequestTelemetry.Operation` enumeration. Its maximum-series budget is 320.
SQL text, statement parameters, relation names discovered at runtime,
connection identifiers, tenants, and correlations are prohibited labels.

`FEAT-OPS-005` can use count distributions and this duration timer together:
count regression locates excess round trips; duration locates slow database
work. Neither substitutes for the request latency SLI.

## Query-Budget Gate

The canonical machine-readable input is
`config/observability/query-budgets.json`. The current Phase 0 reference route
is `platform.getConformanceReference`: fixed overhead 2, slice budget 1, and
maximum 3 statements. Each later route owner must add one unique entry with
`maxQueries = fixedOverhead + sliceBudget`.

Gradle task `queryBudgetGate`, a blocking dependency of `ciStage8`, validates
the catalogue against compiled route identifiers. The retained negative test
adds a reference-slice query and proves the assertion fails. The clean stage 8
run is recorded in `P7.21-clean-pipeline-run.md`.

## FEAT-OPS-005 Intake Criteria

- consume the versioned query-budget catalogue and preserve route identity;
- include `dbQueryCount` and `db_query_duration` in performance evidence;
- fail the performance gate on a budget regression rather than averaging it
  into a latency result;
- add no unbounded or sensitive metric label;
- retain the stage 17 measurement/capacity results under `FEAT-OPS-005`
  ownership rather than claiming them in this foundation feature.
