This record transfers four versioned observability inputs. Publishing an input
does not claim that the downstream dashboards, alert routes, or exercises are
live; those remain `FEAT-OPS-004` deliverables.

## Handover 1 - Registered Metric Inventory

The canonical inventory is
`config/observability/metric-cardinality.json`. Each entry supplies the stable
metric name, permitted labels, and maximum series. The global forbidden-label
set contains `tenantId` and `correlationId`; correlation remains available
through exemplars rather than a time-series dimension.

`FEAT-OPS-004` must build queries from those published names and labels. A
missing or renamed name is a breaking input-contract change, not a dashboard
implementation detail. `MetricCardinalityGate` and CI stage 5 enforce the
inventory before deployment.

Acceptance for intake: catalogue version recorded, all dashboard queries use
declared labels only, and no panel adds a high-cardinality join label.

## Handover 2 - Structured-Log Field Contract

The normative input is `docs/architecture/log-field-contract.md`. Every event
has the required join and workload fields; conditional actor, tenant,
business-event, failure, duration, and query-count fields follow the closed
schema. `actorId` is an opaque safe identifier and is never a name or email.
Secret-shaped fields and arbitrary payloads are prohibited.

`FEAT-OPS-004` may link from a panel or alert to protected log search by
`correlationId`, `traceId`, `errorCode`, `module`, and `slice`. It must not
turn log-only identifiers into metric labels or treat operational logs as the
audit trail.

Acceptance for intake: search templates use canonical field spellings and
retain log-store access controls and the operational-retention boundary.

## Handover 3 - Span Contract

The normative input is `docs/architecture/span-contract.md`. Slice spans use
`<module>.<verbNoun>` and carry the closed attribute set. HTTP, scheduler,
outbox relay, broker consumer, database, Redis, and provider spans preserve
the correlation and W3C trace context rules. Database spans contain statement
names only, never parameters.

Critical exam-entry and grading traces and all errors are retained; standard
traffic uses the approved collector tail-sampling policy. A dashboard or
alert link must navigate by exemplar/trace identity and must not introduce a
new span attribute or expose prohibited content.

Acceptance for intake: trace links resolve from metric exemplar to trace and
from trace `correlationId` to protected logs using the registered field names.
