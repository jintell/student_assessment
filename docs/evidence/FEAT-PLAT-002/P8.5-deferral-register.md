# P8.5 Deferral Register

This register records work deliberately excluded from `FEAT-PLAT-002`. The
persistence feature supplies the database roles, schema ownership, grant
matrix, transaction-local security context, and per-workload pool inputs. It
does not absorb the responsibilities below.

| Deferred capability | Owning feature | Handover from `FEAT-PLAT-002` | Closure evidence |
|---|---|---|---|
| Expand/contract migration discipline and blocking CI stage 12 | `FEAT-PLAT-005` | The separate `app_migrator` entrypoint and per-module Flyway locations | Stage 12 rejects forbidden operations and excessive lock duration, and verifies N-1 compatibility |
| Profile-selected API, worker, and PIN-distribution runtime roles | `FEAT-PLAT-006` | `app_api`, `app_worker`, and `app_pindist` login roles plus the pool-to-role mapping | Role-isolation verification for all three profiles |
| Advisory-lock scheduler singletons | `FEAT-PLAT-006` | Runtime role membership and the platform schema boundary | Exactly one replica wins each scheduled sweep |
| PgBouncer transaction pooling | Phase 2 capacity escalation; operational delivery owner to be assigned when a binding condition is met | Transaction-local `SET LOCAL` role and tenant context makes transaction pooling compatible in principle | Both binding conditions below are satisfied before adoption |

## PgBouncer Binding Conditions

PgBouncer is pre-authorised but is not part of MVP. Adoption is triggered only
if either the API workload must scale beyond 30 replicas or
`ARC-VERIFY-033` demonstrates backend contention rather than CPU as the
limiting resource.

Before adoption:

1. Re-run `ARC-VERIFY-024` through PgBouncer in transaction-pooling mode so the
   adversarial suite covers both application-pool and pooler-level connection
   reuse.
2. Move scheduler singleton locks to a direct non-pooled connection path or
   replace session locks with `pg_advisory_xact_lock`; session-level advisory
   locks are invalid under transaction pooling.

No deferred capability weakens the MVP isolation controls. PgBouncer remains
absent until a trigger and both binding conditions have objective evidence.
