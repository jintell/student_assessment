# P4.25 Lock and Interval Containment

Date: 2026-10-14. Scope: P4.25 and its required P7.19 relay adoption;
counterpart: FEAT-PLAT-004 P7.17. P4.26 is outside this correction.

## Blocker Resolution

The existing advisory locks in audit partition/chain provisioning and outbox
partition maintenance protect database integrity. They are not sweep singleton
mechanisms. No applied migration was edited. `RuntimeSqlResources` pins these
four historical files by path and SHA-256, rejects changed or copied definitions,
and scans every other SQL resource for advisory operations and unresolved
dynamic execution. This explicitly narrows P2.15's historical-resource scope;
the architecture record carries the clarification.

## Blocking Rule

`RuntimeContainmentTests` runs in `conformanceTest`, already required by
`ciStage4`. Its ArchUnit condition checks production classes and reports bounded
`RUNTIME_INTERVAL`, `RUNTIME_LOCK_SQL`, `RUNTIME_DYNAMIC_SQL` and
`RUNTIME_LOCK_ADAPTER` diagnostics with the responsible class/method.

- Only the three exact `RuntimeTickSources` method signatures create periodic
  sources; membership in `platform.infra` alone grants nothing.
- Interval overloads and method references, periodic executor/Scheduler calls,
  Timer, scheduled annotations, unbounded repeats and recursive delayed work
  have negative fixtures. Finite request retry remains valid.
- Only `SessionSweepLock` and `TransactionSweepLock` own runtime lock SQL.
  Other modules consume `SweepLock`; concrete-adapter dependencies are rejected.
- ASM data flow follows literals, constant fields, locals and concatenation
  into SQL sinks, including suppliers, method references and audit statements.
  Unresolved arguments fail closed.
- Eight existing forwarding/query-builder sources are fingerprinted after
  inspection: transaction handles and security/telemetry wrappers forward SQL,
  while existing audit/outbox builders use closed identifiers and bound values.
  Their callers are scanned, literal lock SQL is still prohibited, and source
  changes invalidate the review. There is no package-wide dynamic-SQL exemption.

The extra ASM tree/analysis dependencies use the same pinned version as the
existing ASM visitor. Only conformance compile/runtime lock entries changed.

## Relay Adoption

`RelaySingleton` now acquires the registry-backed `SweepLock` handle and releases
it through `Mono.usingWhen` on success, error and cancellation. Local lock SQL
and FNV key derivation are gone. The central ownership monitor checks during
unfinished work as well as before and after it; missed ownership cancels work.
Acquisition, work and timing remain subscription-deferred.

The PostgreSQL relay test uses the real `outbox-relay` registry row. It verifies
contention and kills the retained coordination backend during an uncommitted
business write, then asserts cancellation, rollback and replacement publication.
This replaces the old fixture's assumption that lock and business SQL share a
database session. Separate transaction/statement timeout coverage remains in
`SessionSweepLockIntegrationTest`.

`SweepRunnerContentionIntegrationTest` drives four actual runners through four
ticks, rotating the winner. It checks four successful batches and twelve skipped
contenders against PostgreSQL for both session and transaction adapters.
