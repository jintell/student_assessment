# P8.8 Runtime Deployment Ordering

Date: 2026-10-16

The release controller must complete the `cbt-migrate` Job before starting any
`cbt-worker` pod on the new image:

```text
build/sign image -> cbt-migrate succeeds -> cbt-api/pindist rollout -> cbt-worker rollout
```

`cbt-migrate` creates and seeds `platform.sweep_registry` and grants its narrow
read access before background scheduling can start. The Job is a hard ordering
barrier: failure aborts the rollout, and worker pods are not started as a
fallback.

If a worker starts before the registry exists or before its rows/grant are
available, `SweepRegistryLoader` fails startup. It must not log the problem and
idle, synthesize registry data, or start only a subset of sweeps. This fail-fast
behavior makes an orchestration defect visible while preventing an apparently
healthy worker from silently omitting mandatory scheduled work.
