# P9.5 Concurrent-Sweep Alert Proposal

Date: 2026-10-16

Status: P1 alert proposed to `FEAT-OPS-004`; no alert rule is claimed live.

## Proposed Rule

`ConcurrentSweepExecution` fires when more than one worker replica reports a
successful execution of the same sweep inside one configured tick window.

The query must group `sweep_tick_total{outcome="success"}` by `sweep` and the
collector's stable pod/instance identity, then count distinct replicas with an
increase in that window. The window comes from `platform.sweep_registry`, not
from a global constant. Restarts must receive a new instance identity so two
lifetimes of one pod are not treated as concurrent replicas.

This is a P1 because it detects failure of the singleton guarantee and possible
duplicate business effects. The alert routes to the stalled-sweep runbook's
lock-holder diagnosis, followed by database/session and deployment rollback
procedures. No tenant or correlation identifier is introduced as a metric
label.

Architecture section 16.4 has no equivalent alert. `FEAT-OPS-004` must select
and validate the infrastructure-supplied instance dimension for the deployed
collector before adopting the rule.
