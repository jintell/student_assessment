# P8.7 Runtime-Role Rollback

Date: 2026-10-16

Rollback is code-only, consistent with `ARC-OPS-006`. Revert all three
workloads to the previous immutable image digest; do not reverse Flyway.

The runtime-role database change is additive:

- `V9__create_sweep_registry.sql` adds `platform.sweep_registry`;
- `V10__seed_sweep_registry.sql` adds static registry rows; and
- `V11__grant_sweep_registry_read.sql` adds the worker's narrow read grant.

The previous image does not depend on or mutate this table. Leaving the table,
grant, and seed rows in place is harmless, preserves forward compatibility,
and keeps version N-1 valid against version N's schema. Once worker pods return
to the previous image, runtime-owned sweep ticks stop; no schema action or data
rewrite is required.

If rollback occurs during a tick, the drain sequence stops new intervals,
finishes or rolls back the active batch at its transaction boundary, and
releases the advisory-lock connection last. Unfinished business work remains
recoverable by its owning feature. Rollback must never drop the registry,
revoke the grant, or delete seed rows under load.
