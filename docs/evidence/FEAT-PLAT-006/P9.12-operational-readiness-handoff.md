## Runtime-Role Checklist

- [ ] `cbt-api`, `cbt-worker`, and `cbt-pindist` each report ready from their
  live management endpoint, use the same immutable image digest, and report the
  matching telemetry role.
- [ ] Every enabled `platform.sweep_registry` row has a deployed definition,
  records ticks, and has a last-success age below three configured intervals.
- [ ] `ConcurrentSweepExecution` is green throughout the observation window;
  evidence shows no two worker replicas successfully execute the same sweep in
  one tick window.
- [ ] The production-shaped shutdown drill is green: readiness drops before
  termination, new work stops, active work commits or rolls back at its safe
  boundary, advisory locks release, recoverable work resumes on another
  replica, and all phases finish inside the grace period with margin.

## Required Evidence

Retain workload revisions and readiness results, shared image digest/SBOM
reference, registry snapshot, sweep tick/last-success graphs, concurrent-sweep
alert history, shutdown phase/abandoned-unit metrics, Kubernetes termination
events, and the drill report. Synthetic data only is used in staging.

## Dependencies and Failure Policy

The review depends on fulfilled runtime provisioning (`P0.8`), adopted alerts
and dashboard panels from `FEAT-OPS-004`, and the scheduled shutdown drill from
`FEAT-OPS-006`. The static templates and Phase 0 integration tests are useful
preconditions but do not replace live evidence.

Any missing role, stale enabled sweep, concurrent execution, killed-before-
drained pod, lost/double-applied work unit, unreleased lock, or exhausted grace
period fails readiness. Do not waive these failures by disabling the alert or
extending the interval/grace period without a reviewed root-cause correction.
