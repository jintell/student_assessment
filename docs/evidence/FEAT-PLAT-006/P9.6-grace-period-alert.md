# P9.6 Grace-Period-Exceeded Alert Proposal

Date: 2026-10-16

Status: P2 alert proposed to `FEAT-OPS-004`; no alert rule is claimed live.

## Proposed Rule

`RuntimeGracePeriodExceeded` fires when Kubernetes terminates a pod after the
termination grace deadline before its shutdown lifecycle completes. Detection
must correlate the pod termination reason/time with the last exported
`shutdown_phase_duration_seconds` and `shutdown_abandoned_units_total` series
for that pod identity.

The alert annotation identifies the runtime role, pod, final observed phase,
configured `terminationGracePeriodSeconds`, and whether queued units were
abandoned. It links the graceful-shutdown runbook. A clean voluntary restart
whose phases finish inside the budget does not alert.

This requires a Kubernetes state/event source because a process killed at the
deadline cannot reliably export a final metric. `FEAT-OPS-004` owns that source
and the final correlation rule. Architecture section 16.4 currently defines no
shutdown condition, so this is recorded as an explicit gap rather than a local
architecture amendment.
