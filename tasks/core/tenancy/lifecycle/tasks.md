**Objective.** Enforce the tenant lifecycle `ACTIVE ⇄ SUSPENDED → CLOSED`. Suspension blocks new work and
initial exam entry without deleting data or destroying in-flight candidate work. Closure permanently blocks
access while retaining data under policy.

**Why this feature is easy to get fatally wrong.** The state machine is three states and four edges. The
difficulty is that "suspended" must mean *no new work* while still meaning *finish the work already
started*. `TENANT-D-001` ratified that recovery of an attempt started before suspension stays permitted,
because the literal reading destroys accepted answers and breaches `NFR-REL-001`. This list goes one step
further: the ratified carve-out is still unreachable, because recovery needs a proctor (`REQ-IAM-029`) and
suspension blocks every proctor (`TASK-TEN2-BLOCKER-001`). Most of the enforcement points also live in
modules that do not exist until Phase 2 and Phase 3 (`TASK-TEN2-DEFECT-001`). So this feature delivers the
state machine, the gate and a **contract every later feature must declare against**. The named regression
test is the permanent proof that the contract held.

### Assumptions

1. **`FEAT-TENANT-001` is delivered as its task list describes.** `tenancy.tenant` carries `lifecycle_state`
   (created `ACTIVE`), `provisioning_status` and `version`, and is a platform-registry table with no RLS
   (`TASK-TEN1-BLOCKER-001`). `P0.2` and `P0.4` confirm this; if either fails, this list waits.
2. **The candidate path has no Keycloak dependency** (`REQ-IAM-031`). The gate on candidate operations
   reads PostgreSQL only.
3. **Answer save, timer refresh and question navigation do not read the gate.** They are `CONTINUATION`, and
   the §15 per-request budget for answer save (6 queries) has no tenant read. This feature must not add one.
4. **Workforce authentication stays with Keycloak.** The platform cannot refuse an IdP login. "Access
   denied" in `AC-TENANT-003-02` is enforced on every workforce request the platform serves
   (`TASK-TEN2-DEFECT-009`).
5. **Phase 1 has no attempts, PINs or sessions.** Enforcement in those modules is tested here against
   test doubles declared with their operation classes. The real modules re-prove it when they land.
6. **Telemetry registration goes through `FEAT-OBS-001`.** Alert rules and panels belong to `FEAT-OPS-004`.
